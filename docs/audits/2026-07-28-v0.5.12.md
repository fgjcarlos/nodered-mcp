# Audit — v0.5.12 (2026-07-28)

Audit of the MCP server for Node-RED, executed on 2026-07-28 against
`fgjcarlos/nodered-mcp v0.5.12` on a real Node-RED 5.0.0 instance
(52 nodes, 3 tabs, debug stream off). The instance was restored to
its original state at the end. Umbrella issue closed: #41.

## 22 tools audited

The 14 read + 8 write. Each finding with a bug has its child issue:
#42 (timeout/retry), #43 (`inject_node` false-positive), #44
(`connect_nodes` / `get_context` hang), #45 (`list_nodes` without
summary), #46 (descriptions and `runtimeState.enabled` precondition),
#47 (`get_debug_messages` off by default), #48 (`get_node_info`
without latest version). The exact list of the 22 exercised was not
preserved in #41; it is reconstructed from the child issues.

## 7 tools NOT audited

By auditor decision not to touch a production OPC UA server.
Suggested reproduction: a disposable Node-RED 5.0.0 container
without OPC UA / species API modules, or a `nodered-test` with
synthetic flows. Coverage should land in a CI job per release
(continues as follow-up of #49, out of scope for this section).

| Tool | HTTP | Risk | Skip reason | Suggested repro |
|---|---|---|---|---|
| `set_flows` | `POST /flows` | write | Replaces the entire flow config | Clean container, test flow, verify the backup is created and the config replaced |
| `restore_backup` | `POST /flows` | write | Restores a local snapshot | Dummy backup created with `list_backups`, verify `flows.json` post-restore |
| `set_flows_state` | `POST /flows/state` | write | Start/stop of the runtime | Container with `runtimeState.enabled = true`, observe `get_flows_state` before/after |
| `install_node` | `POST /nodes` | write | `npm install`, can take minutes | Container with network, verify the module appears in `list_nodes` |
| `uninstall_node` | `DELETE /nodes/:module` | write | Removes from the runtime | Install first, then uninstall, verify absence in `list_nodes` |
| `enable_node` | `PUT /nodes/:module/:set` | write | Toggle module load | Module installed but disabled, enable, verify `loaded: true` |
| `disable_node` | `PUT /nodes/:module/:set` | write | Toggle module load | Module loaded, disable, verify `loaded: false` |

## Caveats

- The exact log of which 22 tools were exercised was not preserved
  in #41. Future audits should attach the run-log at the umbrella
  closure so this table can be filled in automatically.
- The ✅ in the tool tables flags "implemented and green" — the
  audit status column is orthogonal. A tool can be ✅ in the table
  and "not audited" here.
- The audited instance ran with `adminAuth: UNSET` (operator
  decision, not the MCP's). If a future audit runs with admin auth
  enabled, the write tools may have different behaviour at the
  permission edges.

Refs: #41, #49.
