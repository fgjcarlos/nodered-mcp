# scripts/complexity-baseline.txt — issue #73 complexity floor.
#
# Named functions from issue #73 with their current cyclomatic complexity
# (gocyclo). One line per function in the format:
#
#   <func>  <file>  <complexity>
#
# The columns are space-separated. The script reads each line, looks up
# the function in the current gocyclo output, and:
#
#   1. Fails if any value exceeds the agreed threshold (15) — issue #73
#      acceptance criterion.
#   2. Fails if any value increases vs. its baseline — a deliberate
#      regression in complexity is a regression in the codebase.
#
# Bumping a baseline value is a deliberate commit, not an accidental side
# effect of a refactor. The script is intended to be reproduced locally
# and in CI (same tool, same threshold, same parsing).
#
# History of deliberate bumps (most recent first):
#
#   2026-10-26  new floors for the #334 guards  (PR #363, closes #334)
#     The gate only checks the functions named here, so the guards this
#     PR adds were not covered by it. Their floors are added with the
#     values gocyclo reports for them:
#
#       ValidateEffectiveConfig    internal/nodered/validate_deploy.go   3
#       effectiveConfigIssues      internal/nodered/validate_deploy.go   1
#       ownerRuleIssues            internal/nodered/validate_deploy.go   4
#       ownerDocument              internal/nodered/validate_deploy.go  10
#       orphanNodeIssues           internal/nodered/validate_deploy.go   8
#       missingSubflowIssues       internal/nodered/validate_deploy.go   6
#       duplicateIDIssues          internal/nodered/validate_deploy.go   5
#       restoreFlowsLocked         internal/nodered/flows.go             4
#       flatSubflowPortIssues      internal/nodered/validate_deploy.go   7
#       subflowDefinitionPortIssues internal/nodered/validate_deploy.go  7
#       portTargetIssues           internal/nodered/validate_deploy.go   9
#
#     These are new entries, not bumps: no existing floor moves.
#     effectiveConfigIssues is 1 because the per-owner rules were
#     extracted into ownerRuleIssues when the subflow port rules joined
#     it — the extraction the gate asks for, not a floor moved to make
#     a regression fit.
#

#   2026-08-03  synthesizeFlowFromFlat  15 -> 16  (PR #155, closes #147)
#     The function sat exactly at the threshold; any added branch was

#     (current > 15) still applies — a second added branch (17)
#     re-trips the gate. Track a real refactor in a follow-up issue
#     if the function grows further.
#

#
#   scripts/complexity-check.sh --write
#
